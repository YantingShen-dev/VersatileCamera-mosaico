番茄测试照片返回有效新格式（1.41 秒）。薯片/饮品案例目前使用受控模型返回数据，
不代表已经测得真实包装和模糊饮品识别率。

真机更新两次在 Vibe Mode 0.2.1 校验阶段中断，设备返回旧应用 1.1.1，新版尚未部署，
因此新版真机三帧采样、NVS 反复写入和重启保存还未验收，也未存入新的 Vibe Idea。

新识别按“品牌 + 品类”显示，不细分口味。库存内部使用稳定编号；出库只看到
“薯片”时，若库存中只有一种薯片，就扣减对应品牌。存在多个候选时，在取景画面
点选一个；超过三项可以翻页。整张照片的项目全部确定后才一起记账，避免部分扣减。
清楚识别到不同品牌/品类时，不强行扣减其他商品。拍照或返回会取消待选结果。

杯子颜色、泡沫或品牌标志不能确定饮品内容。缺少支持品类的标签文字时，显示饮品
候选供选择，即使库存只有一款也不自动扣减；没有候选时提示对准标签重拍。
这是防误扣机制，不能保证模型永不误读文字。按快门后取三帧、选边缘清晰度最高的
一帧上传，保持实时取景；不是多图视觉比对，也不是自动连续记账。

结果保持静音浮动提示。旧库存迁移为版本 2，保留名称、数量、日期和撤销基线；
以前笼统的“零食”记录不会凭空推断品牌。迁移后的库存不供旧版 1.1.x 读取，
应使用 1.2.0 或更新固件。下面历史说明中与此冲突的命名、播报及确认行为已被替代。

# 连续拍摄与本地播报（1.1.0）

进入入库/出库后先在本机播报“买了些什么？”/“想取出些什么？”。每按一次拍照提交

“+ 苹果 × 1”或“− 苹果 × 1”。保持在取景页，下一次按键继续拍下一批，无需确认。
这不是自动对每一帧入库，避免同一件食品被反复计数。

真机改用 ESP-SR 小乐中文 TTS，逐项合成、逐块播放，语速档位 4，不等待云端音频。

qwen-flash，修改最近一批并从被打断的项目继续播报。说“撤销本次”可撤销最近一批，
“继续播报”恢复，“结束拍摄”回首页。退出取景后关闭 ASR 连接。真机日志已确认食品识别和语音指令解析返回 HTTP 200；真实声场的回声、
打断时延和识别率仍应结合现场体验评估。

# 冰箱库存模拟器：日常有鲜

本版本在电脑上运行真实的 GSP 界面与 C 库存控制器。本地网页提供电脑摄像头、
麦克风、扬声器及模拟按键。另有已上板的硬件预览版，功能范围见下文。

## 启动

在仓库根目录运行：

```powershell
./scripts/fridge-sim.ps1
```

浏览器打开 [体验页](http://127.0.0.1:3223/)。3222 是原生渲染器调试页。
关闭启动终端将停止本次服务；不要同时启动两个占用相同端口的模拟器。
已有模拟器基础依赖见 [电脑模拟器](pc-simulator.md)。额外 Python 依赖：

```powershell
./.venv-sim/Scripts/python.exe -m pip install -r projects/fridge_mosaico/tools/requirements.txt
```

密钥配置保存在 `.mosaico-state/fridge/.env`，按
`projects/fridge_mosaico/tools/env.example` 配置。该目录已被 Git 忽略。
服务只监听本机并检查 Origin/Host；密钥不发送给浏览器。照片和声音会发送给 Qwen。

## 体验流程

1. 选择一张食材照片，或开启电脑摄像头。
2. 需要语音纠正时点击“启用麦克风”，允许浏览器使用麦克风；启动提示与食材播报默认开启。
3. 点击首页底部“入库”进入全屏相机，播报“买了些什么？”，听到后点击“拍照”。
   也可用屏幕外的模拟按键，按一次进入、再按同一个键拍照。
   下方“出库”对应“想取出些什么？”。识别失败重试不会重复启动提示，重新开始一笔才会播报。
4. Qwen3-VL Plus 返回食材列表后，C 控制器立即保存库存并逐项播报。
5. 说“西红柿有3个”，Qwen 实时 ASR 转成文字、Qwen Flash 解释修改，更新本次数量。
   也可以输入文字纠正。“西红柿入库日期改成昨天”会修改本次日期。
6. 点击完成回首页，或撤销本次。首页列表支持按住拖动上下滑动，空库存显示“无”。
   首页底部提供紧凑的入库/出库按钮；取景页叠放小型“拍照”和“返回”按钮，处理中隐藏快门。
   取景画面铺满480×480屏幕，照片中央裁为正方形，上传识别与屏幕画面保持一致。

只有名称、数量、入库日期，不设单位。日期默认电脑当天。数量支持三位小数，
内部定点存储避免累加误差。比如原来5、本次识别2、纠正为3，最终是8。
出库优先扣除最早入库的同名食材；库存不足时整批拒绝，不写成负数。
不确定数量、遮挡和包装可能识别不准，使用语音或文字修正。

库存保存在 `.mosaico-state/fridge/inventory.bin`，带校验及原子写入，重启恢复。
撤销只保留最近一笔，开始下一笔时替换。相机照片保留最后一张在本机忽略目录。
回首页后停止收音，退出页面关闭摄像头。麦克风以16 kHz单声道 PCM 流式传输。
本地 VAD 发现说话先停止播报，最终 ASR 文本通过校验后才修改库存。
识别结果去重并检查会话，过期相片/语音返回不会写入新的事务。

## 联网与音量设置

首页右上角「设置」可打开 Wi-Fi 与播报音量页面；底部入库、出库保持不变。
点击「选择网络」扫描附近 Wi-Fi，列表支持翻页及刷新。点击加密网络后用屏幕键盘
输入密码，按「连接」；密码显示为星号，取消或提交后清空输入。支持普通个人网络
及开放网络，暂不支持隐藏网络或企业认证。连接成功后在 NVS 保存，下次开机会自动重连；
新网络连接失败不会覆盖上次成功的配置。连接等待期间界面仍可返回。

音量通过「-」「+」调节（0–100），「静音」可切换静音和恢复，「试听」播放启动提示。
设备音量在后台保存，重新开机仍保留。模拟器使用电脑的现有网络，不修改 Windows
Wi-Fi；音量作用于伴随页面的浏览器播报。真机 Qwen 需要额外配置 API 凭据；ASR 尚未接入真机。

## 真机 Qwen 配置

在仓库根目录运行 `python projects/fridge_mosaico/tools/provision_device_cloud.py`，
它读取已忽略的本地 `.env`，通过官方 `mosaico.py` 将配置保存到设备 NVS。
凭据不编入固件，不进入浏览器，也不出现在状态日志里。设备独立使用 Wi-Fi 调用
`qwen3-vl-plus` 和 `qwen3-tts-flash`；不需要电脑转发图片。

第二次点击拍照后显示识别等待状态；无食材、HTTP 错误或连接超时会给出明确提示，
不会写入假数据。诊断 RPC 返回真实请求 ID、HTTP 状态、JPEG 大小、耗时与播报字节数。
保存失败或结果过期时不会播报入库成功。设备日期默认为 UTC+8 当天。

识别范围从 1.0.1 起包含所有供人食用或饮用的食品：生鲜、饮料、饮用水、奶制品、
零食、熟食、冷冻食品、罐头和调味品等。包装食品可根据清晰标签识别，不要求露出
内容物；不把包装单独记为库存。每个可见瓶/盒/袋记作 1，不增加单位字段，不将净含量
当作数量，也不推测整包内部个数。明显空包装、餐具和其他非食品仍排除。
完整提示词位于真机 `components/app_cloud/app_cloud.cpp` 的 system message，
模拟器对应 `tools/service.py` 的 `VISION_PROMPT`；两端规则保持一致。
